Where pay gets published, by board

This is a property of the board, not of the employer's generosity: Greenhouse usually carries pay in the description, Ashby ships a structured field, Lever almost never does, Workable does not have a field at all.

What a filtered run costs you

Billing is per returned row, so rows removed by salaryOnly are never charged. Move the slider to see the arithmetic - start fee $0.0005 per run plus $0.0015 per row you keep:

Estimated: $0.1505

Without the filter you would be paying the same $0.0015 per row for a stream that is only ~43% usable, and you would spend your own compute or eyeballs separating the rest.

How to use it

One switch on the ATS Job Feed actor:

{"useVerifiedPool": true, "salaryOnly": true, "maxJobs": 100}

Add "minSalaryUsd": 150000 to keep only postings that clear a floor, or "includeDescriptions": false for a cheaper run that still carries pay for Ashby and Lever (Greenhouse pay lives inside the description, so it disappears in that mode). If you do not want to pay at all, the same numbers are in the free CSV (8,049 rows, CC BY 4.0) and you can check a single employer on the lookup page.

Honest limits

  • This counts published pay, not paid pay. A posting without a range may still pay well - we just refuse to invent a number.
  • Boards differ by design (see the table), so a pool of mostly Lever companies will look much emptier under this filter.
  • Currency is converted with a dated USD table; the rate date is reported as fxDate in each run summary. Unknown currencies stay null.
  • Slugs go stale. When a company moves to a new ATS, that company returns nothing and the run summary names it under failedCompanies instead of silently shrinking.
